# 외부 데이터를 기존 데이터와 어떻게 연결할 것인가

2026-09-23 · 검증된 수치와 설계 제안을 구분해 표기함
관련: `data_interpretation.md`(해석 전제) · `external_data.md`(수집·판정) · `external_eda_findings.md`(도출점)

## 연결 구조

세 데이터의 공간 단위가 다르다. 직접 조인되는 곳과 안 되는 곳을 먼저 구분해야 한다.

| 데이터 | 공간 단위 | 시간 단위 | 축 교차 |
| --- | --- | --- | --- |
| SK 유동인구 | **50m 격자** 19,229개 | 월별 (6시점) | 불가 (주변분포) |
| 신한카드 | 시군구 **2개** | 일별 (184일) | 가능 |
| 외부 자원 | **좌표(점)** | 없음 (스냅샷) | — |

```
외부 자원(좌표) ──거리 계산──> 격자 ──BLOCK_CD 앞 5자리──> 시군구 <──직접──  카드
                              ↑                                    │
                         SK 유동인구                        연령·업종·거주지
```

- **외부 자원 ↔ 격자**: 좌표 거리로 연결된다. 정확한 조인이 아니라 **근접도 계산**이다.
  이미 `preprocessed/grid_access.parquet` 에 구현돼 있다.
- **격자 ↔ 시군구**: `BLOCK_CD` 앞 5자리로 판별된다 (`11230` 강남구, `32010` 춘천시).
  격자를 시군구로 올릴 수는 있지만 **시군구를 격자로 내릴 수는 없다.**
- **카드 ↔ 외부 자원**: 직접 연결 불가. 시군구가 2개뿐이라 관측치가 2개다.

## 1. 검증된 연결 — 격자 지표 × 자원 접근성

격자 단위에서 실제로 계산해 확인한 것이다. 모두 Spearman 상관이며
**팀 표준 250m 격자**(`n = 698 / 7,393`) 기준이다.

| 격자 지표 | × 300m내 통합자원 | × 공공 체육 | × 민간 체육 |
| --- | --- | --- | --- |
| **강남** | | | |
| 고령 비율 | −0.037 (ns) | +0.034 (ns) | **−0.596** |
| 유동인구 규모 | +0.403 | +0.301 | **+0.833** |
| 야간 비중 | +0.029 (ns) | +0.093 (ns) | −0.290 |
| 주말/주중 비 | +0.147 | +0.136 | +0.003 (ns) |
| **춘천** | | | |
| 고령 비율 | **−0.189** | **−0.179** | −0.299 |
| 유동인구 규모 | +0.382 | +0.372 | +0.383 |
| 야간 비중 | **+0.272** | **+0.270** | +0.289 |
| 주말/주중 비 | +0.051 | +0.048 | +0.028 (ns) |

`(ns)` 는 p ≥ 0.01.

### 새로 나온 것 — 공공은 수요를 따라가지 않는다

강남에서 **유동인구 규모 × 민간 체육 = +0.833**, **× 공공 체육 = +0.301**이다.

민간 시설이 사람 많은 곳을 훨씬 강하게 따라간다. 공공도 따라가긴 하지만 결합이 느슨하다.

이것이 "민간 의존 격차"의 **메커니즘 설명**이 된다. 민간은 수요(구매력)를 따라 움직이고,
공공은 다른 논리(행정구역·부지 확보 가능성)로 배치된다. 그 결과 고령 지역에서는
민간이 빠지고 공공만 남는다.

춘천은 공공과 민간이 비슷하게 따라간다(+0.372 / +0.383). 도시 규모가 작아 둘 다 시내 중심에 몰려 있다.

### 춘천의 야간 비중이 자원과 연결된다

춘천은 **야간 비중 × 자원 = +0.272**로 뚜렷하다. 야간 유동인구 비중이 높은 격자는
주거지에 가깝고, 춘천에서는 주거지가 곧 시내 중심이라 자원이 몰려 있다.

역으로 **야간 비중이 낮은 춘천 격자 = 주거 기능이 약하고 자원도 없는 곳**이다.
농촌 지역을 식별하는 실용적인 기준이 된다.

### 쓸 수 없는 연결

**주말/주중 비 × 자원**은 양쪽 다 상관이 +0.05~0.15로 미약하다.
"주말에 사람이 모이는 곳에 여가 자원이 있다"는 직관은 데이터로 지지되지 않는다.
고령 축이나 규모 축에 비하면 설명력이 없다.

## 2. 설계 제안 — Meso(카드) → Micro(격자) 가중

> 아래는 **아직 구현하지 않은 제안**이다. 근거 수치는 검증됐으나 결합 자체는 미구현.

카드는 시군구 2개뿐이라 격자로 직접 내려올 수 없다. 대신 **카드에서 얻은 연령별 계수를
격자의 연령 구성에 곱하는** 방식으로 연결할 수 있다.

### 2-A. 생활 반경 가중치 — **구현했으나 기각**

`notebooks/build_locality.py` · 산출물 `preprocessed/grid_locality.parquet`

#### 설계

카드 데이터2의 연령별 로컬 결제 비율을 격자의 연령 구성에 결합해,
그 격자 인구가 평균적으로 얼마나 지역에 묶여 있는지를 계산했다.

```
locality(격자)    = Σ_연령 [ 격자 연령비중 × 로컬결제비율(지역, 연령) ]
felt_access(격자) = 자원 접근성 × locality
```

카드 연령(10~90대)과 통신 연령(10대~60대이상)의 구간이 달라 60대 이상은 건수 가중 평균했다.

#### 결과 — 격자 가중치로는 쓸 수 없다

| | 평균 | 표준편차 | 범위 |
| --- | --- | --- | --- |
| 강남 | 0.416 | **0.008** | 0.402 ~ 0.450 |
| 춘천 | 0.821 | **0.008** | 0.773 ~ 0.845 |

**격자 간 편차가 거의 없다.** 결과적으로 `felt_access` 는 `opp_n300` 에 상수를 곱한 것과 같다.

| 검증 | 강남 | 춘천 |
| --- | --- | --- |
| `felt_access` × `opp_n300` 상관 | **+0.980** | **+0.995** |
| 하위 25% 격자 겹침 (Jaccard) | **1.000** | **1.000** |
| 새로 편입된 격자 | **0개** | **0개** |

순위가 단 하나도 바뀌지 않았다. 새 정보를 만들지 못한다.

#### 왜 실패했나

로컬 결제 비율의 **연령 간 편차가 지역 간 편차에 비해 너무 작다.**

| | 10대 | 20대 | 40대 | 60대+ |
| --- | --- | --- | --- | --- |
| 강남 | 54.1% | 43.1% | 37.0% | 43.3% |
| 춘천 | 78.2% | 74.1% | 83.9% | 87.0% |

춘천은 전 연령이 74~87% 안에 들어온다. 격자의 연령 구성이 아무리 극단적이어도
가중평균이 그 좁은 범위를 벗어나지 못한다.

앞서 발견한 **U자 곡선은 연령 간 차이가 아니라 지역 간 차이가 압도적이었던 것**이다.
같은 데이터를 다른 축으로 쪼개 보니 드러났다.

#### 살릴 수 있는 부분 — 지역 보정 계수

격자를 구분하는 데는 못 쓰지만 **지역 간 비교에서는 유효하다.**

```
강남 0.416  vs  춘천 0.821   — 2배
```

춘천 사람들은 강남 사람들보다 2배 더 지역에 묶여 있다.
**같은 자원 부족이라도 춘천에서의 타격이 2배**라는 뜻이다.

`external_data.md` 6번의 복지시설 분모 보정(격차 5.3배 → 2.6배)이 이 원리를 쓴 것이다.
지역 단위 지표를 비교할 때는 이 계수를 곱해 보정한다.

### 2-B. 생활 업종 밀집도로 '생활 중심지' 정의

카드 데이터2의 **업종별 로컬 결제 비율**로 생활 업종을 판별할 수 있다
(강남 기준 편의점 69.1% · 약국 69.8% vs 통신요금 9.8% · 세금공과금 21.8%).

로컬 비율이 높은 업종의 결제가 많은 시군구는 생활 중심지 성격이 강하다.
다만 **시군구 2개라 격자로 내려올 수 없다.** 격자 수준 생활 중심지를 정의하려면
통신 데이터(야간 비중·요일 패턴)에 의존해야 한다.

### 2-C. 인구 정규화 분모 보정

`external_data.md` 6번에 정리돼 있다. 고령 유동인구에 로컬 결제 비율을 곱해
거주자 비중을 추정하면 시설당 고령인구 격차가 **5.3배 → 2.6배**로 바뀐다.

## 3. 연결할 수 없는 것

설계 전에 알아야 할 한계다.

**① 고령층의 시간대별 위치를 알 수 없다.**
통신 3개 테이블이 주변분포라 연령 × 시간 교차가 불가능하다.
"고령층이 밤에 어디 있는가", "고령층이 주말에 어느 자원을 쓰는가"는 측정할 수 없다.
야간·요일 지표는 **전 연령 합산**으로만 쓸 수 있다.

**② 자원의 실제 이용을 알 수 없다.**
외부 데이터는 시설의 **존재**만 말한다. 이용자 수·이용 연령·운영 여부는 없다.
"접근성이 좋다"와 "실제로 이용한다"를 구분할 수 없으므로,
**접근성을 이용의 대리 지표로 쓴다는 점을 명시**해야 한다.

**③ 카드 결제를 자원 이용과 연결할 수 없다.**
공공 체육시설·도서관은 대부분 무료이거나 카드 결제가 잡히지 않는다.
카드 데이터로 자원 이용을 검증하는 경로는 막혀 있다.

**④ 시군구 단위 결론은 통계 검정이 불가능하다.**
관측치가 강남·춘천 2개다. 복지시설 구성 비교 같은 분석은 기술 통계로만 쓴다.

## 4. 권장 활용 순서

| 단계 | 연결 | 상태 |
| --- | --- | --- |
| 1 | 외부 자원 → 격자 접근성 | **완료** (`grid_access.parquet`) |
| 2 | 격자 고령 비율·규모 × 접근성 | **완료** (가설 기각, 민간 의존 격차 발견) |
| 3 | 공공/민간 배치 논리 대비 | **완료** (강남 공공 +0.301 vs 민간 +0.833) |
| 4 | 카드 연령별 로컬 비율 → 격자 가중 (2-A) | **구현 후 기각** — 격자 간 편차 없음. 지역 계수로만 활용 |
| 5 | 주민등록 인구로 분모 교체 (2-C) | 외부 데이터 대기 |
| 6 | 복지시설 지오코딩 후 격자 편입 | API 키 대기 |

4번을 구현했으나 기각됐다. **Meso(카드) → Micro(격자) 결합은 현재 데이터로는
연령 축을 통해서는 성립하지 않는다.** 로컬 결제 비율의 연령 간 편차가 지역 간 편차에
비해 너무 작기 때문이다.

Meso → Micro 결합을 살리려면 카드에서 **연령이 아닌 다른 축**으로 격자와 연결할
경로를 찾아야 한다. 업종은 시군구 단위라 격자로 내려올 수 없고(2-B), 일자별 변동은
통신이 월별이라 맞물리지 않는다. **현 데이터 구성에서는 두 데이터를 격자 수준에서
결합할 방법이 없다**는 것이 지금까지의 결론이다.

다음 우선순위는 5번(주민등록 인구)과 6번(복지시설 지오코딩)이다. 둘 다 외부 데이터 대기 중이다.
