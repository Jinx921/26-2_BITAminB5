# 목요일 회의 시연 체크리스트

## 1. WSL에서 백엔드 켜기

WSL 터미널 1에서 저장소 루트로 이동한다.

```bash
cd /home/chaewon/projects/bita-wsl

# 최초 1회에만: 가상환경 생성 및 백엔드 의존성 설치
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r backend/requirements.txt

# 백엔드 실행
uvicorn backend.app.main:app --reload
```

이미 `.venv`와 의존성을 준비했다면 생성·설치 단계는 건너뛰고 활성화한 뒤 실행한다.
서버는 `http://127.0.0.1:8000`에서 열린다. API 문서는
`http://127.0.0.1:8000/docs`에서 확인할 수 있다.

## 2. 실제 API 모드 프론트 켜기

프론트는 `frontend-api-integration` 브랜치의 별도 worktree
(`/home/chaewon/projects/bita-sarang-readonly`)에서 실행한다. 현재 작업 중인
백엔드 브랜치를 바꾸거나 프론트 브랜치의 파일을 수정하지 않는다.

WSL 터미널 2에서:

```bash
git -C /home/chaewon/projects/bita-sarang-readonly branch --show-current
# frontend-api-integration인지 확인
cd /home/chaewon/projects/bita-sarang-readonly/frontend
VITE_API_BASE_URL=http://127.0.0.1:8000 VITE_USE_MOCK=false npm run dev -- --host 0.0.0.0
```

브라우저에서 `http://localhost:5173/login`을 연다. 두 서버를 모두 켜 둔다.
실제 API 모드이므로 로그인에는 미리 준비한 시연 계정이 필요하며,
관리자·현장 담당자 화면은 해당 역할의 계정으로 확인한다. 계정 정보를 문서나
저장소에 적지 않는다.

## 3. 목요일 회의 전 확인 순서

- [ ] **백엔드 health** — `curl -i http://127.0.0.1:8000/health` 응답의 상태가 `ok`인지 확인한다.
- [ ] **로그인 화면** — `/login`이 열리고 준비한 계정으로 시민·관리자·현장 담당자 역할에 맞게 로그인되는지 확인한다.
- [ ] **시민 시설 지도** — 시민 계정에서 지도·시설 정보가 백엔드 API로 표시되는지 확인한다. 표시할 시설 결과가 없으면 질문 제출이 필요할 수 있으므로, 아래 Claude 주의를 먼저 따른다.
- [ ] **지원 요청** — 시민 화면에서 테스트 시설의 지원 요청을 제출하고, 관리자 화면의 요청 목록에 대기 상태로 나타나는지 확인한다. 실제 연락처 등 개인정보는 입력하지 말고 승인된 테스트 데이터만 사용한다.
- [ ] **현장기록** — 현장 담당자 계정에서 준비된 확인 목록을 불러오고 체크리스트를 저장한다. 목록 파일은 미리 준비하고, 저장 완료 여부를 확인한다.
- [ ] **관리자 유형 지도와 현장기록 반영** — 승인된 테스트 동네에 반영 결과를 바꿀 체크리스트 응답(예: `has_residents=no`)을 저장한 뒤 관리자 유형 지도를 다시 불러온다. 제외된 셀은 지도에서 제외 셀 표시를 켜서 확인한다. 현장기록 반영 범위는 관리자 유형 지도다.

> **Claude 질문 주의:** 질문 제출과 현장 확인 목록 생성은 Claude 호출로 이어질 수 있고 비용이 발생할 수 있다. **혜진 언니에게 먼저 확인·승인을 받은 뒤에만** 실행한다. 승인이 없으면 질문을 입력·제출하거나 새 목록을 생성하지 않는다.

## 4. 현재 보류된 기능

- 현장 확인 목록 전달 API: 백엔드에서 목록을 전송·조회하는 API가 없다. 관리자가 내려받은 JSON 파일을 현장 담당자에게 직접 전달하고, 현장 담당자가 화면에서 불러와야 한다. 실제 API 모드에서 가져온 목록은 해당 기기에 임시 보관된다.
- 후보·배치 지도의 별도 프론트 화면: 백엔드 API는 있으나 회의 시연 프론트에 별도 화면이 없다.
- 온라인 배포: 현재 로컬 시연 기준이며 온라인 서비스 주소는 제공되지 않는다.

## 5. 회의에서 받을 피드백 질문

- 시민이 시설을 찾고 지원 요청을 보내는 흐름이 이해하기 쉬운가요?
- 시민 시설 지도에서 시설 위치·정보·범례가 충분히 명확한가요?
- 지원 요청에 필요한 항목과 상태(대기·승인·완료 등)가 적절한가요?
- 관리자 유형 지도에서 유형과 현장기록 반영 결과를 알아보기 쉬운가요?
- 현장 담당자가 확인 목록과 체크리스트를 사용하기 편한가요?
- 후보·배치 지도는 별도 화면으로 제공해야 한다면 어떤 정보와 조작이 우선인가요?
- 현장 확인 목록을 전달할 때 파일 수동 전달 대신 어떤 전달 흐름이 필요한가요?
- 다음 구현·배포 단계에서 우선 해결해야 할 문제는 무엇인가요?
