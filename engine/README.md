# 분석 엔진 (담당: 현준) · v0.2 (2026-10-01)

에이전트가 부르는 도구의 **실제 계산을 전부** 맡는다. 같은 입력이면 항상 같은 결과가 나온다.
LLM은 이 결과의 `evidence` 숫자만 인용해서 설명한다.

## 빠른 사용

```python
import sys; sys.path.insert(0, 'engine')
import core

r = core.classify('춘천')          # 모든 도구가 같은 형식의 dict 반환
r['result']['type_counts']         # {'연계형': 98, '긴급방문형': 55, '예방인프라형': 101, '관찰형': 1361}
r['figures']                       # ['out/types_춘천.png']      → 관리자 화면 그림
r['geojson']                       # 'out/types_춘천.geojson'    → 프론트 지도 API (WGS84)
```

- 전체 예시 생성: `python run_demo.py` → `out/json/*.json`, `out/*.png`, `out/*.geojson`
- 검증: `python -m pytest tests -q` (18개: 팀 후보·민감도 재현·결정성·규격·MCLP 전수탐색 대조·시설변화·caveat·잘못된 입력)
- Claude tool use 정의: `out/tool_schemas.json` (혜진: 에이전트에 그대로)
- **JSON 규격 (혜진·채원·사랑용): [`JSON_규격.md`](JSON_규격.md)**

## 도구 8개 (MVP 6 + 2차 2)

| 도구 | 함수 | 에이전트 구조도 | 한 줄 |
|---|---|---|---|
| 후보 찾기 | `find_candidates(region)` | 후보 찾기 | 낮 활동 지속 저하 고령 거주 칸 |
| 거주 확인 | `check_residential(cell_ids)` | 거주 확인 | 주거/용도미상/비주거/건물없음 |
| 자원 조회 | `lookup_resources(region, cell_id 또는 lat/lon)` | 자원 조회 | 주변 교류·보건 시설과 거리 (시민 모드) |
| 유형 분류 | `classify(region)` | 유형 분류 | 2×2 고립 유형 + 공백 태그 + 원인·추천 표 |
| 배치 시뮬레이션 | `simulate_placement(region, k, radius_m)` | 배치 시뮬레이션 | 이동형 거점 최적 위치(MCLP 정확해) + k 곡선 |
| 강건성 점검 | `robustness(region)` | 강건성 점검 | 기준값별 유형 수·유지율 (검증 에이전트 "재계산") |
| 시설 변화 가정 | `facility_change(region, remove_ids, add_points)` | 시설 변화 가정 | 시설 제거·추가 시 유형 변화 |
| 지역 맥락 | `region_context(region)` | 지역 맥락 | 로컬결제율·60대+ 결제 시간대·인구·독거 |

엔진 밖: 프로그램 검색, 현장 결과 기록, 이웃 연결, 문서 생성 (에이전트·백엔드 담당)

## 현재 결과 (기본값)

| | 후보 | 연계형 | 긴급방문형 | 예방인프라형 | 관찰형 |
|---|---|---|---|---|---|
| 강남 | 51 | 38 | 13 (전부 보건 공백) | 22 | 453 |
| 춘천 | 153 | 98 | 55 (교류 38·보건 12·둘다 5) | 101 | 1,361 |

- 이동형 거점 (긴급방문형 대상, 60대+ 유동 커버): 강남은 반경 1km 2곳이면 100%. 춘천은 반경 1km로 3곳 48%·5곳 62%, 반경 3km(차량)로 3곳 73%·5곳 90%
- 강건성: 강남은 보건 기준(5km면 긴급 0), 춘천은 교류 기준(1km면 긴급 17)과 **SGIS 주택 수 기준**에 민감
  - 춘천 주택 기준 0 / 30(기본) / 100 / 200 → 긴급방문형 167 / 55 / 15 / 2칸. 30은 팀 기준값이라 발표에서 가정으로 밝힐 것

## ⚠️ 유형 해석: 두 층으로 나눠 말하기
- **위축 신호 층 (정책 우선 대상):** 긴급방문형·연계형. 팀 후보(활동 위축) 칸에서만 나옴 (강남 51, 춘천 153)
- **자원 구조 층 (위축 신호 없음):** 예방인프라형·관찰형. 예방인프라형은 어르신 많은 동네 중 자원 공백 (고령 조건 적용 전보다 크게 줄어 춘천 101)
- 발표에서 예방인프라형을 위험 숫자처럼 쓰지 말 것. `classify` 결과의 `layers`, caveats에 자동 표시됨

## 강건성 지표 읽는 법
- `urgent_retained`: 기본 긴급방문형 중 남은 비율 (놓친 칸 확인)
- `urgent_precision`: 새 긴급방문형 중 기본에도 있던 비율 (새로 끼어든 칸 확인)
- `urgent_jaccard`: 둘 다 반영한 겹침. 이걸 대표로 봄
- 야간·주택 기준을 바꾸면 후보를 엔진이 다시 계산한다 (군집은 고정). 강남은 야간 1.3배에서 긴급 13→4
- 사용자 지정 목록에 기본값이 없어도 자동으로 넣어 기본 행을 만든다

## 한계 (답변에 caveats로 자동 포함)

1. 통신 유동은 머무는 사람 기준, 거주자 아님
2. SGIS 값은 1km 격자라 같은 격자 안 250m 칸이 값을 공유 (춘천은 신뢰 격자 적음)
3. 강남 보건 거리는 공공 보건기관 3곳만 (민간 의원 제외)
4. 거리는 직선거리
5. 배치 시뮬레이션의 가중치는 60대+ 유동(체류), 커버는 도달 가능성일 뿐 효과 아님
