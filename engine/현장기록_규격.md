# 현장기록 규격 (채원·사랑용) · 2026-10-12

## 한눈에
- 담당자가 동네(250m 칸)를 방문해 **확인 질문에 답한 결과**를 저장하고, 그중 **두 가지 답만 판정에 반영**한다.
- 반영은 **백엔드가 한다** (에이전트 설계 v2.3에서 합의). 엔진·에이전트 코드는 바꾸지 않는다.
- 대회 기간에는 실제 기록이 없으므로 **가상 기록으로 시연**한다 (예: 춘천 칸 하나에 "사람 안 삶" 기록 → 지도에서 빠짐).

## 1. 흐름

```
에이전트 "현장 확인 목록" (판정이 애매한 동네 + 확인 질문, field_check)
  → 담당자 방문·입력 (프론트)
  → POST /api/v1/field-checks 로 저장 (백엔드, 이미 있음)
  → 백엔드가 아래 2절 규칙으로 판정 덮어쓰기
  → 지도·답변에 반영
```

## 2. 판정 반영 규칙

| # | 현장 답 | 판정 변화 |
|---|---|---|
| 1 | `has_residents` = `no` (사람이 사는 집이 없다) | 판정 대상에서 **제외**. 지도에서 뺀다 |
| 2 | `support_needed` = `not_needed` (지원 불필요) | 유형을 **관찰형**으로 바꾼다 (`priority` 4) |

- 둘 다 해당하면 1번(제외)을 따른다.
- 이 두 가지 외의 답은 **저장만 하고 판정은 바꾸지 않는다.**
- `unknown` / `unsure`는 판정을 바꾸지 않는다.
- 한 칸에 기록이 여러 개면 `checked_at`이 **가장 최근인 기록**을 따른다.
- 원래 엔진 판정은 지우지 않는다. 바꾼 칸에는 표시를 붙여 언제든 되돌릴 수 있게 한다 (3절).

## 3. 저장 형식

기존 API `POST /api/v1/field-checks`의 `checklist` 안을 아래 키로 고정한다.

```json
{
  "cell_id": "4026_7935",
  "checked_at": "2026-10-20T14:00:00+09:00",
  "checklist": {
    "has_residents": "no",
    "social_hard_to_reach": "unknown",
    "health_hard_to_reach": "yes",
    "seniors_out_daytime": "unknown",
    "support_needed": "not_needed"
  },
  "note": "자유 메모 (판정에 쓰지 않음)"
}
```

| 키 | 확인 질문 (에이전트 `field_check` 문구) | 값 | 판정 반영 |
|---|---|---|---|
| `has_residents` | 실제로 사람이 사는 집이 있나요? | `yes` / `no` / `unknown` | 규칙 1 |
| `social_hard_to_reach` | 가까운 경로당·마을회관까지 실제로 걸어가기 어려운가요? | `yes` / `no` / `unknown` | 저장만 |
| `health_hard_to_reach` | 보건소·보건진료소까지 실제로 가기 어려운가요? | `yes` / `no` / `unknown` | 저장만 |
| `seniors_out_daytime` | 낮에 어르신이 밖에 나오시나요? | `yes` / `no` / `unknown` | 저장만 |
| `support_needed` | (종합) 이 동네에 지원이 필요해 보이나요? | `needed` / `not_needed` / `unsure` | 규칙 2 |

- 현장 확인 목록은 동네마다 **해당 질문만** 보여준다. 묻지 않은 항목은 `unknown`으로 저장한다.
- `support_needed`는 모든 동네에서 묻는다. 에이전트 질문 목록에는 아직 없으므로 프론트 입력 화면에 고정 항목으로 둔다.
- 질문 문구는 나중에 바뀔 수 있다. 바뀌면 이 표의 문구만 고치고 키 이름은 유지한다.

## 4. 덮어쓴 결과의 모양

덮어쓴 칸에는 아래 필드를 붙인다. 지도 점(`display.map.points`)과 유형 지도(`types_*.geojson`) 모두 같은 이름을 쓴다.

| 필드 | 값 | 화면에서 |
|---|---|---|
| `field_status` | `excluded`(규칙 1) / `downgraded`(규칙 2) / 없음 | "현장 확인으로 변경" 표시 |
| `engine_type` | 원래 엔진 유형 (예: `긴급방문형`) | 되돌리기·비교용 |
| `field_checked_at` | 반영한 기록의 `checked_at` | 툴팁 |

- `excluded` 칸은 기본 지도에서 숨기고, 관리자가 "현장 확인으로 제외된 곳 보기"를 켤 때만 보여준다.

## 5. 지킬 것
- 현장기록은 **관리자·현장 담당자만** 본다. 시민 화면에 쓰지 않는다.
- `cell_id`는 화면에 글자로 보여주지 않는다 (지도_규격.md와 같음).
- 에이전트 답변 속 숫자(유형 수 등)는 엔진 계산값이라 덮어쓰기가 반영되지 않는다. 화면에 "현장 확인 반영 전 수치"로 구분하거나, 시연에서는 지도 변화만 보여준다.

## 6. 나중에 (확장)
- "저장만" 하는 세 가지 답이 쌓이면 기준값(교류·보건 거리, 위축 기간, 주택 기준) 조정 근거로 쓴다.
